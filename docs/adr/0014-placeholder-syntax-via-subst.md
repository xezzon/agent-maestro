# 0014: 占位符语法采用第三方库 subst

#60 要在配置值里支持 `${}` 插值。经决定不自研解析、改用成熟社区库、占位符语法遵循库。我们**暂时**采用 `subst`（shell-like variable substitution，0.3.x）：`${name}` 与短式 `$name` 引用变量，`${name:default}` 提供内联默认值（默认值内部递归替换），反斜杠转义 `$ \ : { }`；变量名为 `[A-Za-z0-9_]+`（允许数字开头）。宿主把合并后的变量表（`BTreeMap`/`HashMap`）交给它；未定义变量、畸形占位符、非法转义一律返回带 `source_highlighting` 的错误，满足「未解析即显式失败」。它支持 `Template` 解析一次、对每个插件 `expand` 多次。

这使 `$` 与 `\` 不再是普通字符：字面 `$` 必须写 `\$`、字面 `\` 必须写 `\\`；参与插值的值里形如 `sk-$abc` 的串会被当作引用变量、串尾 `$` 会报错。即 #60 原文 requirement 5「字面量 `$` 可表达」需靠转义满足、requirement 6「既有配置零影响」不再成立。项目尚无发布版，迁移代价≈0；用户今后在参与插值的值里填含 `$`/`\` 的内容须自行转义，此约束写进 SDK README。`api_key` 与模型 `id` 后来被排除在插值外（见 ADR 0015），凭证里的 `$` 按字面量保存、无需转义。pi 等工具自身的 `$VAR`/`$$` 语义在**工具侧**，与本层不冲突但需在文档里区分。

`${name:default}` 与 ADR 0015 的变量表并存而不冲突：只要名字在合并后的表里存在（全局表项或插件覆盖命中），就优先于内联默认值；`:default` 只是「名字未声明也不报错」的旁路。我们不禁止它（禁止即自己插手语法，违背「遵循库」）。此外 `:` 被默认值占用，`${env:…}` 这类命名空间形态在本语法下不可表达——与「本期不做环境变量」一致。

本选择是**临时**的（「暂时先用 `subst`」）：它为唯一已知的硬伤（`$` 须转义）保留了换库空间。为此，验收要求**用测试钉住所选库的语义**（占位符、转义、未闭合 / 空名 / 非法、未定义变量、`$` 与 `\` 的处理），一旦升级或更换库改变了行为即红，换库成本因此可控。

曾考虑并否决：**自研解析**（题目明令禁止，且错误定位与边界处理远不如成熟库）。**`strfmt`**（`{name}`、`{{`/`}}` 转义、无内建默认值）——它对 `$`/`\` 完全不特殊，#60 关心的「api_key 含 `$`」被完整满足，且没有内联默认值这一旁路；代价是把 `{`/`}` 变成特殊字符（字面花括号须转义、孤立花括号报错）。`$` 在密钥与 URL 中比花括号更常见，但本轮仍选了更贴近 #60 原始 `${}` 设想、生态更成熟的 `subst`；既然是临时决定，若 `$` 转义在实践中被证明是负担，可切回 `strfmt`，或改用 `minijinja`/`handlebars` 一类 `{{ }}` 引擎（后两者是完整模板引擎，语法面与攻击面更大，未予采纳）。
