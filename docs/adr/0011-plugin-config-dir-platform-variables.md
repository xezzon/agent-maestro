# 0011: config_dir 以平台变量前缀声明，解析归 manifest.rs

插件的写入面由 manifest 的 `config_dir` 声明（见 ADR 0004），宿主在装载时把它解析为绝对路径，并在投影时预开放为组件内的 `/`。原声明只接受 `~/…` 形式，于是在 Windows/macOS 上只能落到主目录下的同名目录，表达不了 `%APPDATA%\zed`、`~/Library/Application Support/zed` 这类真实位置；而插件是同一份 wasm 二进制，编译期拿不到宿主 OS，平台解析只能由宿主做。我们决定把声明升级为**平台变量前缀 + 相对片段**：`$HOME`、`$XDG_CONFIG_HOME`、`$LOCAL_APP_CONFIG`、`$XDG_DATA_HOME`、`$LOCAL_APP_DATA` 五个变量（`~` 与 `$HOME` 同义，兼容既有 manifest；不提供 cache），每个变量按当前平台解析（`dirs`，Linux 遵循 XDG 环境变量）为该变量对应的基准目录，声明的相对片段拼在其后。解析函数从插件服务搬到 `plugin/manifest.rs`，与 manifest 的解析校验同处一地；`config_dir` 的类型直接是路径，装载时把声明原位替换为解析出的绝对路径（不留「声明」与「解析结果」两个字段并存），投影按它预开放目录。

同一份声明因此在三个平台各得其所：`$XDG_CONFIG_HOME/zed` 在 Linux 是 `~/.config/zed`、在 macOS 是 `~/Library/Application Support/zed`、在 Windows 是 `%APPDATA%\zed`；`$LOCAL_APP_CONFIG`/`$LOCAL_APP_DATA` 对应 Windows 的 `%LOCALAPPDATA%`（其余平台与 `$XDG_CONFIG_HOME`/`$XDG_DATA_HOME` 同值）。校验规则：变量必须出现在最前、且是支持的五个之一；相对片段不得为空、不得是绝对路径、不得含 `..`、不得是裸 `.`（即解析后与基准目录重合的形态，包括 `$HOME/.` 与 `$HOME/./x`）；目录不存在时先创建；随后按规范化的真实路径确认**严格落在**该变量对应的基准目录内——与基准目录相等同样视为逃逸（防裸 `.` 在任何路径上的回退写法），符号链接逃逸也在这道关里被拒。违规即 manifest 校验失败——不落位、不写配置条目、界面直接显示原因，与既有的安装期 fail-fast 一致。投影报告的完整性不受影响：`write-providers` 仍返回相对 `config_dir` 的路径，宿主按解析结果拼成宿主绝对路径，界面据此展示完整路径并打开。

曾考虑并否决的形态：**把写入根改为组件在运行时声明**（WIT 升 2.0.0、新增 `host.declare-write-roots`，一个插件可声明多个根，宿主按平台基准的变体类型解析、在投影调用内挂载）——它换来的能力（一个插件写多个目录、路径知识留在插件代码里）对当前工具都不是必要条件，却要引入新合同、新的 SDK 适配层，以及「声明必须是组件在该实例里对文件系统的第一个动作」这类只在实测中才暴露的时序陷阱（组件侧预开放表是首次路径解析时的一次性快照），实现与心智成本不成比例，整体放弃。给每个平台显式列一串路径（`map<平台, 路径>`）——把平台知识摊给每个插件作者，且宿主得解析多种字面量语法。只保留 `~`、另设一个 Windows 专用字段——两个字段表达同一件事，长期靠约定维持一致。把 cache 也纳入变量表——当前没有工具需要写缓存目录，变量越少校验面越小，将来需要再加（新增变量是兼容变更）。
