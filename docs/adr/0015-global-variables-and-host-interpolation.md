# 0015: 全局变量与宿主侧插值

不同工具往往需要略微不同的值——例如同一网关下 `https://gateway.ai/${ACCOUNT_ID}/${GATEWAY_ID}` 各插件要不同的 `GATEWAY_ID`，只能改全局配置时一处改动会波及其它工具。我们决定引入**变量**：全局配置顶层一段 `variables`（名 → 默认值，默认值**必填**），全局配置里的字符串值可用占位符引用变量；每个插件可在自己的**插件配置**（ADR 0017）里按名覆盖变量的值，未覆盖即用默认值。

覆盖模型只有**变量覆盖**一种：要让某字段按插件差异化，就把它参数化成变量，而不另开「逐字段覆盖」的机制——两套能表达同一意图的机制会带来优先级心智与长期漂移，收益只是省一次参数化。「按插件选择一部分 provider/model」属于**结构**（哪些实体参与投影）而非**值替换**，本期不做。也不引入环境变量作为取值来源：桌面应用继承的环境取决于启动方式（桌面图标 / 终端 / IDE 各不相同），会让「同一份配置在两种启动方式下行为不一致」，且无法在配置里声明；#60 里「机器相关的值」属于跨设备同步那条线，届时再设计，将来若加是兼容性追加。

**解析**由宿主在投影时执行，且**按插件**解析一次——把「全局变量表」与该插件的 `variables` 覆盖合并后对全部 provider 插值，**先插值、后映射端点**（宿主按非空判定收集端点，`${EMPTY}` 解析为空串即按未配置端点处理；用哪个端点投影已移交插件裁定，见 ADR 0016）。**作用域**＝全局配置中的一切字符串值（新增字段自动纳入，见 #58 的 `custom_header`）；**例外**（后续修订）：`api_key` 与模型 `id` 原样保留、不参与插值——模型 id 是标识符，与 `plugins` 段的 `source`/`id` 同类；api_key 是凭证，按字面量保存与投影，值里的 `$`/`\` 无需转义。**不做链式解析**（变量值里的占位符原样输出）；不含 `plugins` 段的 `source`/`id`、不含插件 `form`；数字字段不是字符串、天然不参与。

**失败语义**：任一字段解析失败即把该插件整体置 `failed`、**不调用插件、不写任何文件**，原因含 slug + 字段名 + 变量名/库报错，不含值、不含密钥（守 ADR 0008）。不采用「跳过单个 provider」——插件是**整文件重写**，跳过一个 provider 会让它从工具配置里被删掉，比整体失败危险；既有的 `SkippedProvider`（端点为零，双端点已不再跳过、见 ADR 0016）是**合法配置状态**，与插值的**错误**不同类。插件配置读取/解析失败同样整插件 `failed`，不静默降级为「无覆盖」——静默降级会让用户以为覆盖生效了。

**落盘前一致性校验**（后续补充）：provider 新增与更新、变量表整包保存时，宿主用（变更后的）变量表对受影响 Provider 预插值一次，任一引用不可解析或占位符语法错误即拒绝、不落盘；变量名合法性（ADR 0014 的 `[A-Za-z0-9_]+`）同在保存前校验，空默认值合法（`${EMPTY}` 解析为空串即按未配置端点处理）。落盘不变式＝存储写出的全部 Provider 对当前变量表可插值，错误在录入时暴露而非等到投影；报错与投影时同因同报（slug + 字段名 + 变量名/库报错）。手工改坏配置文件仍会让投影失败——该不变式只约束存储自身的写路径。

**后续修订（#94）——Provider 启用状态与插值的关系**：Provider 新增 `enabled`（默认启用，旧配置缺字段视为启用）。这是**全局**的结构过滤——某条 Provider 是否参与一切投影——与上面「按插件选择一部分 provider」的逐插件结构覆盖是两回事，后者仍未做、仍受本节约束。**过滤发生在命令层**（`apply_providers` 读取配置时即挑出 `enabled` 者，见 `command::plugin::enabled_providers`），`write_providers` 与插值函数本身都不感知 `enabled`、对传入的每一项都插值——单一职责。这与「不采用跳过单个 provider」不冲突：被跳过者正是用户显式声明不参与投影的条目，其从工具配置消失是预期结果，而非插值**错误**造成的静默丢弃；参与投影的 Provider 仍适用「任一字段失败即整插件 failed」。**落盘不变式不变**：存储写出的全部 Provider（含禁用者）对当前变量表可插值，故 `create_provider`/`update_provider`/`set_variables` 的校验对禁用者同样不豁免（禁用只是投影时的结构过滤，改变不了存储内容是否自洽）。切换 `set_provider_enabled` 本身不改变任何占位符文本，而存量记录此前已过上述校验，故该命令无需再次校验。

`CONFIG_VERSION` 保持 1：加顶层 `variables` 是增量字段（`serde(default)`），旧文件照常读入、新应用对旧文件得空表。代价是**降级**时旧应用会整段丢弃 `variables`、并把占位符当字面量投影出去；项目尚无发布版，接受。

占位符的具体语法不属本 ADR，见 ADR 0014。曾考虑并否决：环境变量、逐字段覆盖、链式解析（要定义环检测与解析顺序，成本远高于收益）、失败时跳过单个 provider（见上）、为变量表单设文件或导航项（变量属全局配置，与 provider 同页）。
