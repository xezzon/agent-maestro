# 0019: 重叠字段由插件裁定投影优先级

Maestro 的模型元数据里会出现**表达同一事实的多个字段**：`capabilities` 的 `image_in`（#58）与保留字段 `modalities.input`（Kilo 语义的输入形态集合）都回答「这个模型能不能收图」。我们决定**不**在 Maestro 侧做去重或一致性校验——两个字段都照常保存、照常交给插件，冲突时**用哪一个由插件裁定**，Maestro 只负责记录。

这与 ADR 0016 建立的「宿主映射、插件裁定」是同一姿态：宿主决定谁进入列表（结构过滤），插件决定进入者用哪个端点。Maestro 的领域模型因此可以比任何单个工具的表达能力更宽——同一事实允许有多个来源与多个粒度，把「取哪个」留给最了解目标工具的那一端。代价有两处：插件作者必须自己定义并**写下**它的优先级规则（参考实现见 `plugins/pi/README.md`），且 Maestro 无法在录入时提示「这两个字段自相矛盾」。

曾考虑并否决的形态：**录入时拒绝重叠字段**（强迫用户按 Maestro 的单一词汇表思考，而各工具的词汇表本来就不同，等于把工具差异泄漏进领域模型）；**只保留一个权威字段**（工具需要另一种粒度时，要么改字段语义触犯 ADR 0004 的 major，要么再加一个字段，重叠届时又回来）；**由 Maestro 定义优先级并投影出合并后的单一值**（把工具专有的语义判断焊进 Maestro，与「插件适配工具差异」的分工相抵）。
