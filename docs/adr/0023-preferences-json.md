# 0023: 用户偏好存于 `~/.maestro/preferences.json` 独立 JSON 文件

用户偏好（主题等界面级选择）需要持久化，但它与 Provider、变量、插件等**领域配置**是不同类的数据：领域配置是投影的数据源头，损坏不可容忍（ADR 0001：坏文件拒绝写入，绝不静默覆盖）；偏好只关乎应用外观，读不出来时安全退回默认值即可，不应阻塞应用。因此偏好不并入 `config.json`，而是落在与之并列的顶层文件 `~/.maestro/preferences.json`，由 Rust 侧统一读写（启动时加载、变更即时原子写盘）。代价是 `~/.maestro` 顶层出现两个 JSON 文件，相对目录布局收敛的方向是一次显式妥协，换来的是两份数据的读写路径、容错策略与版本号（`PREFERENCES_VERSION` 与 `CONFIG_VERSION`）各自独立演进、互不牵连；两条路径由同一个路径助手（`paths.rs`）导出，将来若要合并布局只改一处。

容错策略与领域配置相反，是「读取宽松、兜底并重写」：文件不存在按默认值创建；缺字段补默认值并写回；主题值非法兜底并落盘修正；JSON 语法损坏先把原文件留档为 `preferences.json.bad`（再次损坏覆盖留档）再写默认值，不静默销毁；`version` 不符时按默认值运行、不读写该文件；任何写回失败只记日志 WARN，不阻断启动。命令边界则相反地严格：未知主题值在反序列化时即被拒绝，由前端保证只发合法值。

「跟随系统」依赖宿主报告操作系统的明暗外观；无 portal 的 Linux 环境（无 D-Bus、部分 Flatpak 沙箱）收不到系统外观及其变化，此时「跟随系统」等价于固定亮色——这是宿主能力边界，非本应用可修。
